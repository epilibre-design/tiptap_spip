# Compatibilité SPIP 4.2 et 5 — Plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** vérifier le critère 8 de la spec 08 (« fonctionne dans l'espace privé SPIP 4.2, 4.4 et 5.x ») sur des sites jetables, et corriger ce qui casse.

**Architecture :**
- **Sites jetables**, à côté de `/src/jetables/v4.4.21` (conservé, intouché) :
  - **SPIP 4.2.16** : `/src/jetables/v4.2.16`.
    - Archive `files.spip.net/spip/archives/spip-v4.2.16.zip`, la dernière 4.2.
    - SQLite, serveur `php8.3`, puisque SPIP 4.2 s'arrête à PHP 8.3, sur `127.0.0.1:18932`.
    - Plugins : Crayons 3.5.1, plus les liens vers `tiptap_spip`, `tts_test` et `tiptap_spip_faq`.
  - **SPIP 5.0-dev** : `/src/jetables/v5.0-dev`.
    - Branche `master` de `git.spip.net/spip/spip`, installée par `composer install`. Il n'y a pas de 5.0 publiée ; la version déclarée est `5.0.0-beta`.
    - SQLite, serveur `php8.4` sur `127.0.0.1:18933`.
    - Pas de Crayons : même `master` déclare `[4.1.0;4.*]`.
  - Installation par l'installateur web (formulaires remplis par un script hors dépôt), admin `id_auteur` 1.
- **Chargement du noyau dans les scripts de test :**
  - `tests/charger_spip.php` regroupe le code de démarrage, jusque-là copié dans trois scripts : `site.php`, `propre.php` et `exporter.php`.
  - Il couvre les trois dispositions :
    - **4.2 :** `vendor/` sans kernel, donc `ecrire/inc_version.php` ;
    - **4.4 :** `Kernel\param` ;
    - **5 :** `Spip::param`, puisque `Kernel\param` est déprécié.
- **e2e :**
  - `TTS_PHP` choisit le binaire PHP du pilote (`php8.3` pour la 4.2).
  - Les tests Crayons sont sautés quand le plugin n'est pas installé sur le site.

**Tech Stack :** inchangée.

## Global Constraints

- **Contraintes des lots précédents :**
  - commentaires en français, tabulations ;
  - commits sans trailer ;
  - aucune chaîne en dur ;
  - bundle reconstruit et versionné s'il change.
- **Site `/src/jetables/v4.4.21` conservé :** ni suppression, ni réinitialisation. Les nouveaux sites suivent la même règle.
- **Pas de régression sur SPIP 4.4 :** e2e trois navigateurs, Vitest, PHPUnit et équivalence inchangés.

## Tâches

1. **Sites jetables 4.2.16 et 5.0-dev :** installation, plugins, serveurs.
2. **Chargement du noyau :** `tests/charger_spip.php` et `TTS_PHP`. Vérification : `propre.php` et `site.php config` sur les trois sites.
3. **e2e Chromium sur 4.2 :** relever les échecs, en corriger la cause (code ou test).
4. **e2e Chromium sur 5.0-dev :** chargement par l'importmap et `_inits/80_tiptap_spip.js`, extensions tierces avant le lancement, formulaires CVT, Crayons sauté.
5. **Firefox et WebKit** sur les deux sites.
6. **Équivalence** (`scripts/equivalence.mjs`) contre l'oracle 4.2 et 5 : relever les écarts de rendu propres à une version.
7. **Specs 08 (critère 8) et 09 :** versions vérifiées, écarts connus.

## Réalisation

- **Sites :** installés comme prévu, par l'installateur web. Les deux serveurs tournent avec `PHP_CLI_SERVER_WORKERS=4` : SPIP 4.2 s'appelle lui-même au premier rendu public (`config/.ok`, `vendor/.ok`), ce qui bloquait environ 70 s un serveur à processus unique.
- **Lancement SPIP 5 refait (écart au plan) :** le lancement par `_inits/` ne fonctionnait pas.
  - SPIP 5 concatène `_inits/` en un fichier statique, gardé tant que le cache de `_init.js` dure (100 h) et que `suivre_invalideur()` ne régénère pas. La configuration du plugin n'y était pas reprise, et `prive` y valait `false` (SPIP 5 passe `prive => true`, le squelette attendait `oui`). L'éditeur ne se montait qu'à la faveur d'un `public: true` resté en cache.
  - Le chemin `prive` du plugin faisait aussi charger ce lancement sur toutes les pages publiques.
  - Désormais, SPIP 4 et 5 passent par `tiptap_spip_head()` (`header_prive`, `insert_head`). La configuration (`prive/javascript/tiptap_spip_config.js.html`) est posée dans le module de lancement. En SPIP 5, le module importe `'tiptap_spip.js'` et `'ajaxCallback.js'` par l'importmap : un plugin tiers qui importe `tiptap_spip.js` partage le même module.
  - `_inits/80_tiptap_spip.js` est supprimé, ainsi que la clé `css` de la configuration, qui ne servait qu'à lui.
- **Glossaire SPIP 5 :** `traiter_raccourci_glossaire()` n'y est plus qu'un bouchon. L'URL est calculée par un `PreLiensEvent`, comme le fait `expanser_liens()` : `pipeline('pre_liens', $texte)` passerait un tableau à `tw_autoliens()`.
- **Scripts de test :** `tests/charger_spip.php` charge le noyau des trois versions. `site.php`, `propre.php` et `exporter.php` cassaient en SPIP 4.2, dont le `vendor/` n'a pas de kernel. `TTS_PHP` désigne le PHP du pilote.
- **e2e :**
  - les tests Crayons sont sautés sans le plugin ;
  - le test du formulaire public déclaré attend l'instance, que le lancement crée après l'import des extensions tierces (échec intermittent sous WebKit).
- **Équivalence :** `ecarts.yaml` accepte `branches` (diff figé et justification propres à une branche majeure de SPIP) ; `propre.php --branche` donne celle de l'oracle. `code-accoles` a un diff propre à SPIP 5.
- **Régressions de SPIP 5 trouvées en route, signalées sur `spip/ecrire` :**
  - un cookie `spip_session` vide ou mal formé donne une erreur 500 sur tout le site : `effacer_cookie_session()` appelle `spip_setcookie()` sans charger `inc/cookie` ;
  - `src/Texte/Collecteur/HtmlTag.php` : la balise fermante `[^>]*` absorbe `</code` dans `<code>a</code</code>`, d'où une perte de texte.
- **Résultats :**
  - PHPUnit 43 ; Vitest 570 ;
  - équivalence 27/28 sur les trois oracles ;
  - e2e sur trois navigateurs :

    |---|---|---|
    | SPIP 4.2.16 | 124 | 5 |
    | SPIP 4.4.21 | 124 | 5 |
    | SPIP 5.0-dev | 115 | 14 |
